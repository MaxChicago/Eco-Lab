# ВАРИАНТ 1
## Задание 1. Жизненный цикл ПО (3–4 балла)
Жизненный цикл ПО — время от решения создать программу до её полного снятия с использования. В него входят все этапы разработки, внедрения и сопровождения.
Основные этапы:
Анализ требований — выясняют, что должна делать система.
Проектирование — создают архитектуру и модели системы.
Реализация — пишут код программы.
Тестирование — проверяют программу на ошибки.
Внедрение — устанавливают программу у заказчика.
Сопровождение — исправляют ошибки и дорабатывают систему.
Вывод из эксплуатации — прекращают использование программы.
Последовательность: Анализ → Проектирование → Реализация → Тестирование → Внедрение → Сопровождение → Вывод из эксплуатации.
## Задание 2. Диаграмма вариантов использования (5–6 баллов)
Назначение — показать, кто работает с системой и какие функции она даёт пользователям.
Актёр — человек или другая система вне нашей программы, которая с ней взаимодействует.
Прецедент — действие системы, полезное для актёра (например, «Оформить заказ»).
Отношение include — один прецедент всегда включает другой. Стрелка: базовый → включаемый, <<include>>.
Отношение extend — один прецедент иногда дополняет другой (по условию). Стрелка: расширение → базовый, <<extend>>.
## Задание 3. Функциональное и юзабилити-тестирование (7–8 баллов)
Функциональное тестирование — проверка, правильно ли программа выполняет свои функции по требованиям.
Юзабилити-тестирование — проверка, удобно ли пользоваться интерфейсом программы.

## Задание 2. Инкапсуляция, наследование, полиморфизм (5–6 баллов)
Инкапсуляция — данные и методы объединены в объекте, а внутреннее устройство скрыто. Снаружи видны только нужные операции.
Наследование — новый класс берёт свойства и методы старого класса и может добавить свои.
Полиморфизм — разные объекты по-разному выполняют один и тот же метод (один интерфейс — разные реализации).
## Задание 3. Диаграмма классов (7–8 баллов)
Назначение — показать классы системы, их поля, методы и связи между ними.
Класс — описание объектов с одинаковыми данными и поведением. На схеме — три части: имя, атрибуты, методы.
Интерфейс — список методов без реализации. Класс должен эти методы реализовать.
Видимость — + public (всем), − private (только внутри класса), # protected (класс и потомки), ~ package (в пакете).
Множественность — сколько объектов связано друг с другом: 1, 0..1, *, 1..*. Пример: у заказа 1..* позиций.

Назначение — показать, в каком порядке объекты обмениваются сообщениями во времени.

## Задание 2. Управление конфигурацией ПО (5–6 баллов)
Управление конфигурацией ПО — учёт состава программы и контроль её изменений. Нужно знать, какая версия что содержит и кто что менял.
Идентификация конфигурации — присвоение уникальных имён и номеров версий файлам, модулям и релизам.
## Задание 3. Agile (7–8 баллов)
Agile — гибкий способ разработки: короткие циклы, частая поставка рабочей программы и готовность менять требования.
Принципы Agile:
Часто давать заказчику ценное рабочее ПО.
Принимать изменение требований.
Поставлять ПО часто (недели).
Бизнес и разработчики работают вместе.
Доверять мотивированной команде.
Лучше общаться лично.
Главный показатель — рабочее ПО.
Держать устойчивый темп работы.
Следить за качеством кода и дизайна.
Делать проще, без лишней работы.
Команда сама организует работу.
Регулярно улучшать процесс.
