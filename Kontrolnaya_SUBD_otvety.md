# ВАРИАНТ 2

## Задание 1. Теория (макс. 2 балла)

**Первичный ключ (PK)** — атрибут (или минимальный набор атрибутов) отношения, однозначно идентифицирующий каждый кортеж (строку). Значения PK уникальны и не могут быть NULL.

**Внешний ключ (FK)** — атрибут (или набор атрибутов) одного отношения, значения которого совпадают со значениями первичного ключа другого отношения. Обеспечивает ссылочную целостность между таблицами.

**Принципиальное различие:** PK идентифицирует записи **внутри своей** таблицы; FK обеспечивает **связь между таблицами**, ссылаясь на PK другой таблицы.

## Задание 2. ER-модель «Авиаперевозки» (макс. 4 балла)

**Условие:** самолёт может назначаться на несколько рейсов, на конкретный рейс — только один самолёт. Каждый самолёт обязательно назначается хотя бы на один рейс, каждый рейс обязательно обслуживается самолётом.

### Сущности и атрибуты

| Сущность | Атрибуты |
|----------|----------|
| **САМОЛЁТ** | `Бортовой_номер` **[PK]**, `Марка`, `Вместимость`, `Командир` |
| **РЕЙС** | `Номер_рейса` **[PK]**, `Дата_вылета`, `Время_вылета`, `Бортовой_номер` **[FK]** → САМОЛЁТ |

### Связь

- **Название связи:** «назначение»
- **Тип связи:** **1:N** (один-ко-многим) — один самолёт → много рейсов
- **Класс принадлежности:** обязательная — обязательная
- **Внешний ключ:** в подчинённой сущности **РЕЙС** (`Бортовой_номер` [FK])

### Схема ER (текстово)

```
САМОЛЁТ (1) ———«назначение»——— (N) РЕЙС
                                    ↑
                              Бортовой_номер [FK]
```

## Задание 1. Теория (макс. 2 балла)

**Транзакция** — логически упорядоченная последовательность операций с базой данных, которая либо выполняется целиком, либо не выполняется вовсе (принцип «всё или ничего»).

**Свойства ACID:**

| Буква | Свойство | Смысл |
|-------|----------|--------|
| **A** | Atomicity (атомарность) | Транзакция выполняется целиком или откатывается полностью |
| **C** | Consistency (согласованность) | БД переходит из одного согласованного состояния в другое |
| **I** | Isolation (изолированность) | Параллельные транзакции не мешают друг другу |
| **D** | Durability (долговечность) | После COMMIT результат сохраняется даже при сбое |

# ВАРИАНТ 5

## Задание 1. Теория (макс. 2 балла)

**Тип связи** — количественное соотношение экземпляров двух связанных сущностей (сколько экземпляров одной сущности могут быть связаны с экземплярами другой).

**Виды типов связи:**

1. **1:1** (один к одному) — один экземпляр первой сущности связан ровно с одним экземпляром второй, и наоборот.
2. **1:N** (один ко многим) — один экземпляр первой сущности связан с несколькими экземплярами второй; у экземпляра второй — только одна связь с первой.
3. **M:N** (многие ко многим) — несколько экземпляров первой сущности связаны с несколькими экземплярами второй.

**Класс принадлежности** — характеристика обязательности участия экземпляра сущности в связи.

**Виды класса принадлежности:**

1. **Обязательный (total)** — каждый экземпляр обязан участвовать в связи.
2. **Необязательный (partial)** — экземпляр может не участвовать в связи.

## Задание 1. Теория (макс. 2 балла)

**Представление (View)** — виртуальная таблица, содержимое которой определяется SQL-запросом. Представление не хранит данные самостоятельно (за исключением материализованных представлений), а формирует результат при каждом обращении.

**Основные цели использования:**

1. **Безопасность** — ограничение доступа к отдельным столбцам или строкам.
2. **Упрощение запросов** — скрытие сложного SQL от пользователя.
3. **Независимость от схемы** — стабильный интерфейс при изменении базовых таблиц.
4. **Удобное представление данных** — объединение данных из нескольких таблиц в одну логическую структуру.

    Маршрут.Название_маршрута,
